# 安全基线与测试工程规范

## 1. 安全基线（一票否决项）
1. **默认拒绝原则**：除明确标注公开的路由（如健康检查、登录）外，业务接口默认要求鉴权守卫。
2. **防越权（IDOR）**：凡按 ID 查询、修改、删除资源的接口，必须在服务/数据层校验资源归属权（`tenantId` / `ownerId`），不得仅依赖客户端传参。
3. **防注入与路径穿越**：数据库查询严格使用参数化绑定，禁止字符串拼接 SQL；文件下载/读写接口必须校验路径白名单。
4. **幂等与限流**：涉及创建订单、扣费、状态流转、短信/邮件发送的接口必须具备幂等控制或速率限制。

## 2. 测试编写规范
1. **AC 显式映射**：每个测试用例的描述中标注对应的需求验收标准编号（如 `[AC-1]`），便于 Reviewer 与人工门禁核验。
2. **AAA 结构**：统一采用 Arrange（准备）→ Act（执行）→ Assert（断言）三段式，单测之间禁止共享可变全局状态。
3. **真实断言**：严禁编写永远为真的占位断言（如 `expect(true).toBe(true)`），错误分支必须断言具体的错误码与副作用。
4. **隔离外部依赖**：单元测试必须 Mock 第三方 HTTP/LLM/支付接口，确保离线与沙箱内 100% 稳定复现；真实数据库联调放入 E2E 测试套件。

## 3. 门禁完整性约束
- 若门禁失败，必须修复业务代码或补充正确测试，严禁删改既有断言、屏蔽类型检查或跳过用例。
